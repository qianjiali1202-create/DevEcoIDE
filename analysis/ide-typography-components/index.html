主流 IDE 对照与鸿蒙电脑尺度建议

从竞品差异、中文阅读和键鼠 / 触屏任务出发，推导适合鸿蒙电脑的设计参数。

6 个 IDE 对照3 个体系有部分数值依据官方文档 · 源码 · Figma
HARMONYOS PC / 键鼠优先，兼顾触屏

建议从 14/20、28 行高、32 控件高开始验证。

桌面 IDE 需要维持扫描密度，中文说明需要更充分的行距，触屏则需要独立的点击空间。由这三类需求推导一套鸿蒙电脑候选方案，而不是直接采用某家 IDE 的规范。IJ 只承担展示组件来源。

14fp常规 UI 字号20 fp 行高 · 导航 / 表单
28vp密集列表行高文字20 + 上下各4
32vp常规控件高文字20 + 上下各6
6vp基础圆角候选与 R4 / R8 同尺寸验证
推荐值的性质这些是本研究的设计选择，不是竞品数值的平均数、鸿蒙官方强制规范或用户实测最优值。字体使用 fp，布局使用 vp；网页以默认比例模拟，不能用 CSS px 直接替代鸿蒙真机校准。

从市场观察到方案选择

桌面密度 → UI 14/20

IJ / VS 基础 UI 提供13字号参考；Zed普通标签语义尺寸为14。选择14是中文界面的验证起点，20行框为混排留余量；不推导“行业统一14”。[S01、S05、S14]

按任务分层 → 不全局放大

代码14/22独立调节；AI长文本16/24；辅助文字12/16。文件树继续保留之前的16字号项目约束，避免把所有文字都压成14。

偶尔触屏 → 扩大真实目标

保留键鼠主工作区密度，提供触屏增强。主要触控目标按48×48候选验证；密集列表切换48行高，不让扩大热区相互覆盖。[S15–S18]

可见按钮 ≠ 实际点击目标

鸿蒙方案示意
32 vp 可见控件 / 48 vp 点击高度

此示例整块外层都是按钮；仅加一个不响应点击的 wrapper 不算热区。

48来自既有跨端触屏规则的参考方向，不作为所有键鼠列表行的高度要求。图示用网页逻辑尺寸模拟。

先验证14，再保留16的选择

默认14/20、28高列表在336高内容视口中显示12整行；阅读增强16/22、32高显示10整行；触屏48高显示7整行。

“能显示更多行”只表示几何容量。真正的取舍需要比较定位时间、误点、长名称截断和阅读舒适度。

值得带回方案的三个观察

从13到14的常规UI样本

IJ / VS提供13参考；Zed普通标签是14，而全局字号设置16是另一层含义。鸿蒙建议14/20是场景取舍，不是行业平均数。

同字号可以有不同密度

VS 基础行高 18.2 与 IJ 组件行框 16 来自不同实现。真实密度还取决于容器、padding、是否换行与字号缩放。

可配置性影响采样

编辑器、终端、AI 阅读区需要分别记录。用户导入配置后的页面，不能被当作出厂默认界面。

INT UI KIT / LIGHT

把看得见的尺寸，与组件外框分开。

此页仅说明用于搭建报告的 IJ 原始组件，不是鸿蒙电脑推荐方案。下方样本按所读节点实现。组件外层用浅色辅助线标记；参考数值均来自本次读取的 Community 文件，不宣称适用于全部 IntelliJ 版本。

C · 方案 / 待测

14/20、16/22、16/24以及R6/R12均为方案参数。没有本机测量的竞品不提供虚构精确值。

下一轮验证怎么做

  1. 记录环境：产品版本与构建号、操作系统、浅色主题、UI 缩放、编辑器缩放、显示器倍率、字体回退与是否导入设置。
  2. 固定样本：同一中英文项目名、长路径、三层目录、相同代码与 336 px 列表视口；分别记录 UI、编辑器、终端和 AI 阅读区。
  3. 测量边界：字体设置值、文字行框、容器矩形、可见边框、点击命中区域分别记录。原生 pt 与物理截图像素先校准，不直接换算。
  4. 验证体验：让开发者完成定位设置、阅读说明、选择列表项等任务；记录截断、误点、定位时间与主观舒适度。当前仅完成原型布局与交互验证，不声称效率提升。
